## 2. Grill-me 问题树

### Q1：用户看到“连接中”时，需要系统展示什么？

推荐答案：不仅显示“连接中”，还应显示：正在探测的后端 URL、WebSocket URL、上一次 HTTP/WS 错误、当前端口占用进程、是否命中旧端口兼容路径。

当前实现状态：后端端口已迁移到 `18080..18100`，前端兼容旧 `8000..8020`；UI 诊断细节仍可继续增强。

### Q2：下一轮 GUI 重构是否可以重写业务核心？

推荐答案：不可以。下一轮 GUI 重构应优先拆分 `apps/frontend/src/components/trading-dashboard.tsx`，保留 `apps/frontend/src/lib/dashboard-api.ts` API 契约和 `apps/backend/app.py` 产品适配层。

### Q3：持续学习系统应该做到什么程度？

推荐答案：下一阶段先做简单、可解释的记忆入口：历史决策案例、收益结果、标签、按模型/Agent 隔离读取；避免过早引入复杂向量知识库。

### Q4：事件驱动系统下一步优先级是什么？

推荐答案：优先把交易时间、系统事件、公告/新闻输入做成可视化时间线和 Agent 输入流；真实新闻/公告源接入作为下一轮候选，不阻塞当前 handoff。

### Q5：是否需要用户现在申请额外信息？

推荐答案：本地离线和桌面/modern-ui 验证不需要额外申请。在线运行需要用户本地 `.env` 维护 Tushare token、LLM gateway base URL/API key；不得写入 Git 或文档。

### Q6：外部调研如何进入开发？

推荐答案：使用 `smart-search` 作为首选外部检索工具；如果 provider/网关失败，记录阻塞原因，不伪造调研结果。已有同类项目对比见 `docs/technical/COMPARISON.md`。

### Q7：哪些流程应该固化为 skill / hook？

推荐答案：已固化交付闭环 skill、pre-commit 文档同步检查、post-commit 自动推送、Cursor stop hook；本次新增 handoff skill，用于下一轮 AI 接手前强制阅读计划和检查未提交变更。

## 3. 当前仍开放但不阻塞交接的问题

| 问题 | 推荐默认处理 |
| --- | --- |
| 下一轮是否优先 GUI 重构还是真实新闻/公告源？ | 推荐先 GUI 诊断与组件拆分，因为它直接解决“黑箱”和“连接中”问题。 |
| 是否安装第三方 Trellis skill？ | 暂不安装。`npx skills find` 找到的 Trellis/handoff skill 安装量较低，应先用项目内文档和 skill 固化。 |
| 是否启用逐条 shell approval hook？ | 不启用。当前强制点放在 pre-commit、post-commit、Cursor stop hook，避免开发被频繁阻塞。 |
