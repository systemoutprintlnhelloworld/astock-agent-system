# TUI UX / 可观察性重构计划

更新时间：2026-06-09

## 背景

GUI 已可用，但当前阶段优先把 TUI 做成长期并存的调试/长程运行入口。TUI 与 GUI 必须共用 `apps/backend` FastAPI 契约，不复制交易业务逻辑；TUI 只负责配置、命令交互、运行可观察性和终端友好的交易看板。

## 外部参考结论

本轮通过 smart-search 获取并参考：

- `earendil-works/pi`：强调 agent runtime、TUI library、差分渲染、可从任意目录启动和会话可分享。
- `claude-code-best/claude-code`：强调 slash 命令、命令候选解释、权限/沙盒/memory 等长期会话能力。

对 AStock 的落地约束：

1. 交易透明性优先于“对话拟人化”。默认右侧必须是交易/持仓/盈亏看板，而不是帮助或状态文本。
2. 命令发现要像 coding agent：输入 `/` 自动展示候选命令和说明，继续输入时过滤，而不是只靠 Tab。
3. 初始化配置只放基础运行参数；比赛模型是运行前/运行中的 Agent 并行配置，不应放在首次初始化里。
4. 配置应尽量单选/多选，避免手打逗号列表；默认模型来自后端模型列表，支持模糊过滤。
5. `/start` 后必须立即展示 run 观测视图：run_id、运行状态、排行榜、持仓、交易、决策日志和后续可用命令。
6. 历史配置和旧输出不应一直堆在屏幕上遮挡输入；TUI 每次关键命令后应重绘主界面，并把状态条放在 prompt 附近。

## 本轮实现任务

1. 初始化向导：数据模式用单选，provider chain 用多选，默认模型从模型列表模糊选择，比赛模型移出初始化。
2. 命令面板：`/` 自动弹出命令候选，候选含说明；二级命令/参数也显示说明。
3. 看板默认：`/dashboard` 默认交易看板，`/dashboard status` 才展示状态。
4. 运行观测：新增 `/run` 和 `/dashboard run`，`/start` 后自动切到运行视图。
5. 屏幕重绘：减少历史输出堆叠；每次命令后重绘 20/80 主布局，底部显示状态栏。
6. 验证：用实际后端命令验证 `/models`、`/dashboard`、`/start`、`/run` 链路，最后运行 `./start.bat -Mode delivery-check`。
